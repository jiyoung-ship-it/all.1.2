# 나만의 Python 퀴즈 게임

## 1. 프로젝트 소개

Python으로 제작한 터미널 기반 객관식 퀴즈 게임입니다.

사용자는 기본으로 제공되는 퀴즈를 풀거나 직접 새로운 퀴즈를 추가할 수 있습니다.

퀴즈 문제는 무작위 순서로 출제되며, 사용자가 풀 문제 개수를 선택할 수 있습니다.

퀴즈 결과는 100점 만점으로 계산하고, 힌트를 사용하면 해당 문제의 획득 점수가 감소합니다.

전체 퀴즈 목록, 최고 점수, 풀이 기록은 JSON 파일에 저장되어 프로그램을 종료하고 다시 실행해도 유지됩니다.

### 개발 목적

- Python의 기본 문법과 입출력 이해

- 조건문, 반복문, 함수 활용

- 클래스와 객체지향 프로그래밍 적용

- JSON 파일을 활용한 데이터 영속성 구현

- 입력값 검증과 예외 처리 학습

- Git과 GitHub를 활용한 버전 관리 실습

## 2. 퀴즈 주제 및 선정 이유

### 주제: Python 기초 프로그래밍

Python을 처음 배우는 학습자가 기본 개념을 복습할 수 있도록 Python 기초 문법을 주제로 선정했습니다.

출력 함수, 자료형, 조건문, 함수 정의, 리스트 등의 개념을 객관식 문제로 구성했습니다.

기본 문제는 총 5개이며, 사용자가 새로운 문제를 추가하거나 기존 문제를 삭제할 수 있습니다.

## 3. 개발 환경

- 개발 언어: Python 3.14

- 개발 도구: Visual Studio Code

- 운영체제: macOS

- 버전 관리: Git

- 원격 저장소: GitHub

- 외부 라이브러리: 없음

- 사용 라이브러리: json, random, datetime, pathlib (Python 표준 라이브러리)

Python 3.10 이상에서 실행할 수 있도록 작성했습니다.

## 4. 주요 기능

### 4.1 퀴즈 풀기

- 등록된 객관식 문제를 무작위 순서로 출제

- 사용자가 풀 문제 개수 선택

- 문제마다 4개의 선택지 제공

- 1~4번 중 정답 입력

- 정답과 오답 판정

- 정답 개수 및 최종 점수 출력

- 최고 점수 자동 갱신

- 등록된 퀴즈가 없는 경우 안내 메시지 출력

### 4.2 퀴즈 추가하기

- 새로운 문제 직접 입력

- 선택지 4개 입력

- 정답 번호 1~4 입력

- 힌트 선택 입력

- 입력값 검증

- 추가한 문제를 JSON 파일에 저장

### 4.3 퀴즈 목록 보기

- 기본 퀴즈와 추가한 퀴즈 출력

- 문제 및 선택지 확인

- 정답 번호 확인

- 등록된 힌트 확인

- 퀴즈가 없는 경우 안내 메시지 출력

### 4.4 최고 점수 확인

- 퀴즈 완료 후 최고 점수 기록

- 기존 최고 점수보다 높으면 갱신

- JSON 파일에 저장하여 재실행 후에도 유지

- 기록이 없는 경우 안내 메시지 출력

### 4.5 퀴즈 삭제하기

- 등록된 퀴즈 목록 출력

- 삭제할 문제 번호 선택

- 삭제 전 확인 메시지 출력

- 삭제한 내용을 JSON 파일에 반영

- 삭제 취소 기능 제공

### 4.6 풀이 기록 보기

- 퀴즈를 완료할 때마다 풀이 기록 저장

- 날짜 및 시간 기록

- 푼 문제 수와 정답 개수 기록

- 힌트 사용 횟수 기록

- 최종 점수 기록

- 프로그램 재실행 후에도 기록 유지

### 4.7 종료

- 메뉴에서 7번을 입력하면 정상 종료

- 종료 시 JSON 데이터 저장 시도

- Ctrl+C 및 EOFError 발생 시 안내 메시지 출력

- 가능한 범위에서 데이터를 저장하고 안전하게 종료

## 5. 보너스 기능

### 5.1 랜덤 출제

\`random.sample()\`을 사용하여 문제를 중복 없이 무작위로 선택합니다.

### 5.2 문제 수 선택

등록된 퀴즈 수를 기준으로 사용자가 풀 문제 개수를 선택할 수 있습니다.

### 5.3 힌트 기능

Quiz 클래스에 \`hint\` 속성을 추가했습니다.

- 힌트가 등록된 문제는 해당 힌트 출력

- 힌트가 없는 문제는 오답 선택지 2개 제거

- 문제당 힌트 1회 사용 가능

- 힌트 없이 정답: 100점

- 힌트 사용 후 정답: 50점

- 오답: 0점

최종 점수는 선택한 문제 수를 기준으로 100점 만점으로 계산합니다.

### 5.4 퀴즈 삭제

사용자가 등록된 퀴즈를 삭제할 수 있습니다.

삭제 결과는 JSON 파일에 반영되며, 프로그램을 재실행해도 유지됩니다.

### 5.5 점수 기록 히스토리

\`datetime\` 모듈을 사용하여 퀴즈 완료 날짜와 시간을 기록합니다.

모든 완료된 게임의 점수를 저장하고, 메뉴에서 이전 기록을 조회할 수 있습니다.

## 8. JSON 데이터 저장 방식

프로그램은 프로젝트 루트의 \`state.json\` 파일에 데이터를 저장합니다.

파일 인코딩은 UTF-8이며, 한글 데이터도 저장할 수 있습니다.

### 저장 데이터 예시

\`\`\`json

{

    "quizzes": [

        {

            "question": "Python에서 함수를 정의하는 키워드는?",

            "choices": [

                "class",

                "def",

                "import",

                "return"

            ],

            "answer": 2,

            "hint": "함수를 정의할 때 사용하는 키워드입니다."

        }

    ],

    "best_score": 80.0,

    "history": [

        {

            "date": "2026-11-12 14:30:25",

            "total": 5,

            "correct": 4,

            "hints_used": 0,

            "score": 80.0

        }

    ]

}

\`\`\`

위 데이터는 저장 형식을 설명하기 위한 예시입니다.

실제 \`state.json\`에는 현재 등록된 모든 퀴즈와 완료된 게임 기록이 저장됩니다.

### 데이터 구성

\| 항목 | 의미 |

\|------|------|

\| quizzes | 현재 등록된 전체 퀴즈 목록 |

\| question | 문제 내용 |

\| choices | 4개의 선택지 |

\| answer | 정답 번호(1~4) |

\| hint | 힌트 내용 또는 null |

\| best_score | 최고 점수(0~100) 또는 null |

\| history | 완료된 퀴즈 풀이 기록 목록 |

\| date | 퀴즈 완료 날짜와 시간 |

\| total | 푼 문제 수 |

\| correct | 정답 개수 |

\| hints_used | 힌트 사용 횟수 |

\| score | 해당 게임의 최종 점수 |

### 저장 및 불러오기

- 프로그램 시작 시 \`state.json\`을 읽습니다.

- 저장 파일이 없으면 기본 퀴즈로 시작합니다.

- 파일 내용이 손상된 경우 백업 복원을 시도하고, 복구할 수 없으면 자동 저장을 중단합니다.

- 새로운 퀴즈를 추가하면 저장합니다.

- 퀴즈를 삭제하면 저장합니다.

- 퀴즈를 완료하면 최고 점수와 풀이 기록을 저장합니다.

- 프로그램 종료 시에도 저장을 시도합니다.

- UTF-8 인코딩으로 한글 데이터를 처리합니다.

- 이전 버전의 JSON 데이터 형식도 불러올 수 있도록 구현했습니다.

### JSON 데이터 구조를 선택한 이유

\`quizzes\`는 여러 개의 문제를 저장하므로 리스트 형태로 구성했습니다.

각 문제는 질문, 선택지, 정답, 힌트를 하나의 묶음으로 관리하기 위해 딕셔너리 형태로 저장합니다.

\`best_score\`는 게임 전체에서 하나의 최고 점수만 관리하므로 최상위 항목에 저장합니다.

\`history\`는 여러 번의 풀이 결과를 순서대로 보관하기 위해 리스트로 구성했습니다.

이러한 구조는 게임에서 사용하는 데이터를 역할별로 구분하고, 필요한 값을 쉽게 조회하거나 수정하기 위한 설계입니다.

### JSON 저장 방식의 한계

JSON은 사람이 읽기 쉽고 Python 표준 라이브러리만으로 사용할 수 있다는 장점이 있습니다.

하지만 다음과 같은 한계가 있습니다.

1. **데이터가 많아질수록 성능 저하 가능성:** 전체 JSON 파일을 읽고 다시 저장하는 방식에서는 데이터가 증가할수록 처리 시간이 길어질 수 있습니다.

2. **메모리 사용량 증가:** \`json.load()\`는 파일 내용을 Python 객체로 변환하므로 데이터가 커질수록 메모리 사용량이 증가합니다.

3. **동시 접근 문제:** 여러 프로그램이 같은 JSON 파일을 동시에 수정하면 변경 내용이 덮어써질 수 있습니다.

4. **데이터 구조 변경의 어려움:** 저장 필드가 추가되거나 변경되면 이전 버전 데이터와의 호환성을 고려해야 합니다.

5. **파일 손상 위험:** 저장 도중 프로그램이 종료되거나 오류가 발생하면 파일이 손상될 수 있습니다.

### JSON과 데이터베이스 비교

\| 구분 | JSON 파일 | 데이터베이스 |

\|------|-----------|--------------|

\| 사용 목적 | 소규모 데이터 저장 | 중대형 데이터 관리 |

\| 설치 및 설정 | 비교적 간단 | 종류에 따라 추가 설정 필요 |

\| 데이터 검색 | Python에서 직접 처리 | SQL 등으로 조건 검색 가능 |

\| 데이터 수정 | 전체 파일 재저장이 필요할 수 있음 | 필요한 데이터만 수정 가능 |

\| 동시 접근 | 별도 제어 필요 | 동시 접근 및 트랜잭션 기능 제공 가능 |

\| 확장성 | 데이터 증가 시 관리가 어려워질 수 있음 | 대량 데이터 관리에 유리 |

현재 프로젝트는 기본 문제 5개와 사용자가 추가하는 소규모 퀴즈 데이터를 관리하므로 JSON을 선택했습니다.

향후 사용자 수와 데이터가 증가하거나 여러 사용자가 동시에 접근하는 기능을 개발한다면 SQLite 또는 MySQL 같은 데이터베이스 도입을 고려할 수 있습니다.

### 데이터 구조 버전 관리

현재 저장 데이터는 \`quizzes\`, \`best_score\`, \`history\`를 중심으로 구성되어 있습니다.

향후 데이터 구조가 변경될 경우 \`schema_version\`과 같은 버전 필드를 추가하면 저장 형식의 차이를 구분하는 데 도움이 됩니다.

예를 들어 새로운 필드가 추가되었을 때 저장된 버전을 확인하고 이전 데이터를 새로운 구조로 변환하는 방식으로 확장할 수 있습니다.

이 내용은 향후 개선 방향이며, 현재 버전 필드가 구현되었다는 의미는 아닙니다.

### 파일 손상 및 복구 정책

프로그램은 `state.json`의 유효성을 검사하며, 정상 저장 데이터를 `state.json.bak`에 자동 백업합니다.

- 기존 원본이 유효하면 저장 전에 백업 파일을 갱신합니다.
- 첫 저장 시 백업 파일이 없으면 저장된 원본을 복사해 백업을 생성합니다.
- 원본이 없거나 손상되면 백업 파일을 검증한 뒤 복원을 시도합니다.
- 손상된 원본은 가능한 경우 `state.json.damaged`로 보관합니다.
- 원본과 백업 모두 읽을 수 없으면 기존 데이터 보호를 위해 자동 저장을 중단합니다.
- 임시 파일에 JSON을 기록한 뒤 `os.replace()`로 원본을 교체하여 저장 중 파일 손상 위험을 줄입니다.

**주의:** 백업은 직전의 유효한 저장 상태일 수 있으므로, 복구 시 가장 최근 변경 사항까지 모두 복원된다고 보장할 수는 없습니다. 실제 파일 손상·복원 테스트 결과는 별도로 증빙해야 합니다.

## 9. 입력값 검증 및 예외 처리

- 메뉴 번호는 1~7만 허용합니다.

- 정답 번호는 1~4만 허용합니다.

- 문제 개수는 등록된 퀴즈 수 범위 내에서 선택합니다.

- 입력값 앞뒤 공백을 제거합니다.

- 빈 입력에 대한 안내 메시지를 출력합니다.

- 잘못된 숫자나 문자 입력을 처리합니다.

- 문제와 선택지의 빈 문자열을 허용하지 않습니다.

- Ctrl+C 및 EOFError 입력을 처리합니다.

- JSON 파일 누락, 손상 및 파일 입출력 오류를 처리합니다.

- 프로그램 종료 시 가능한 범위에서 데이터를 저장합니다.

## 10. 객체지향 설계

### Quiz 클래스

퀴즈 게임 전체를 관리합니다.

### 객체지향 설계를 선택한 이유

이 프로젝트에서는 퀴즈 문제 하나를 관리하는 기능과 게임 전체를 관리하는 기능을 구분하기 위해 객체지향 프로그래밍을 적용했습니다.

\`Quiz\` 클래스는 문제 내용, 선택지, 정답, 힌트를 하나의 객체로 묶어 관리합니다.

\`QuizGame\` 클래스는 여러 \`Quiz\` 객체를 관리하면서 메뉴 실행, 점수 계산, 기록 저장 등 게임 전체의 흐름을 담당합니다.

객체지향 설계를 선택한 주요 이유는 다음과 같습니다.

1. **재사용성:** \`Quiz\` 클래스를 사용하여 같은 구조의 문제 객체를 반복해서 생성할 수 있습니다.

2. **유지보수성:** 문제 자체의 기능과 게임 운영 기능을 구분하여 수정할 수 있습니다.

3. **확장성:** 새로운 문제 유형이나 기능을 추가할 때 기존 구조를 활용할 수 있습니다.

4. **역할 분리:** 클래스마다 담당하는 기능이 구분되어 코드의 목적을 이해하기 쉽습니다.

5. **데이터 관리:** 문제 데이터와 관련 동작을 하나의 객체에서 관리할 수 있습니다.

## 14. Git 브랜치 병합 검증

별도의 작업 브랜치에서 문서를 수정하고 커밋한 후, main 브랜치로 병합하여 Git 협업 과정을 검증했습니다.

병합 시 --no-ff 옵션을 사용하여 브랜치 병합 이력이 Git 그래프에 남도록 했습니다.

커밋 10개 이상 증빙: https://github.com/jiyoung-ship-it/all.1.2/commits/main/

### 브랜치 사용 목적

브랜치는 main 브랜치의 안정적인 코드를 유지하면서 새로운 기능이나 문서를 별도로 수정하기 위해 사용합니다.

작업이 완료되면 해당 브랜치의 변경 사항을 main 브랜치에 병합합니다.

### 브랜치 이름 규칙

브랜치 이름은 작업 목적을 쉽게 구분할 수 있도록 작성했습니다.

- \`feature/\` : 기능 개발 작업

- \`docs/\` : 문서 수정 및 검증 작업

예를 들어 \`feature/quiz-play\`는 퀴즈 플레이 기능 작업을 의미하며, \`docs/merge-verification\`은 병합 과정을 검증하는 문서 작업을 의미합니다.

### --no-ff 옵션을 사용한 이유

\`git merge --no-ff\`는 빠른 전진 병합이 가능한 상황에서도 별도의 병합 커밋을 생성하도록 하는 옵션입니다.

이를 사용하면 기능 브랜치가 어느 시점에 main 브랜치에 병합되었는지 이력에서 확인하기 쉬워집니다.

다만 \`--no-ff\`는 병합 충돌을 자동으로 해결하는 옵션은 아닙니다.

### 브랜치 병합 과정

1. main 브랜치에서 작업 브랜치 생성

2. 작업 브랜치에서 기능 또는 문서 수정

3. 변경 사항 커밋

4. main 브랜치로 이동

5. 작업 브랜치 병합

6. Git 로그를 통해 병합 이력 확인

7. GitHub에 변경 사항 업로드

## 16. 향후 개선 방향

현재 프로젝트의 주요 기능과 보너스 기능은 구현되어 있지만, 안정성과 확장성을 높이기 위해 다음 개선 사항을 고려하고 있습니다.

1. **자동 백업 및 복원:** \`state.json.bak\` 파일을 활용한 데이터 손상 복구 기능

2. **안전한 저장:** 임시 파일 저장 후 원본 교체 방식 검토

3. **자동 테스트:** 메뉴 입력, 퀴즈 추가·삭제, 저장·불러오기 테스트 자동화
